# Verification evidence

This report distinguishes measured behavior from assumptions. The receipts contain synthetic test tasks, not credentials or general chat exports.

## Environment

- Pi `1.0.2`.
- Node `v26.10.0` on Linux.
- Running T3 Code `v0.0.46-nightly.20261004.2644`.
- Real child provider `pi`, model `openai-codex/gpt-5.5`.
- T3 source inspection used pingdotgg/t3code commit `eac52f0087d9ba5dee5542f24788d1482affae43`. The integration ran against the installed T3 environment, not a newly built copy of that checkout.

## Offline and actual RPC checks

[local-checks.txt](local-checks.txt) records passing unit/lifecycle/resource tests, TypeScript checking, actual Pi RPC command tests, and the package-manifest check. GitHub Actions reruns these checks on Node 24 and 26 without live credentials.

The 21 tests cover tool-name resolution, duplicate/tagged T3 responses, nested permission failures, provider/model selection, explicit option validation, stable launch/cancellation identities, missing transport and missing launch receipts, role loading, session mode activation/restoration, compatibility aliases, confirmation behavior, migrated skills, and the real plan validator.

The RPC smoke test starts a real Pi process. It verifies command registration, a persisted mode-off entry, and the outside-T3 diagnostic. It does not contact a model or pretend to test delegation.

## Real child work and cancellation

[live-e2e.json](live-e2e.json) is generated by `npm run test:live`. Its parent is a **real Pi SDK agent loop with a deterministic fixture stream**. The child runs are **real T3-owned Pi processes using a live authenticated model**. Child summaries are not mocked.

The test:

1. Loads Constellation and T3's actual generated Pi bridge.
2. Runs calls through Pi's tool pipeline and observes nested T3 hooks.
3. Rejects an unknown model before delegation.
4. Launches two distinct asynchronous children in one parent tool batch.
5. Gives the worker a broken arithmetic function and a real Node test. The worker fixes subtraction to addition.
6. Independently runs the same test in the parent. The receipt includes the fixed source, test source, test output, and before/after SHA256 values.
7. Gives a report-only reviewer a separate synthetic file. The parent compares hashes to prove the file stayed unchanged during that run. This is a behavior observation, not permission enforcement.
8. Uses test-only idempotent durable waits to prove retrying the same request returns the same task, not a duplicate launch. Production Constellation remains async-only.
9. Cancels a third task, observes `cancel_requested`, then confirms terminal `interrupted`.
10. Reads a completed task through Constellation's status tool.

`sourceSha256` seals the extension, role, skill, package, and live-runner files used for that test. To verify that the receipt matches this checkout:

```bash
python3 - <<'PY'

root = pathlib.Path('.')
evidence = json.loads((root / 'evidence/live-e2e.json').read_text())
assert evidence['passed'] is True
for path, expected in evidence['sourceSha256'].items():
    assert hashlib.sha256((root / path).read_bytes()).hexdigest() == expected, path
print('Verified', len(evidence['sourceSha256']), 'source hashes')
PY
```

## Native T3 automatic delivery

[native-delivery.json](native-delivery.json) was independently extracted from T3's durable thread activity. This test used an **actual T3-managed LLM Pi parent**, with the installed Constellation package and no Herdr subagent host.

The timeline records:

- `constellation_roles` and `constellation_catalog` calls.
- `constellation_delegate` and its nested T3 `delegate_task`, launched in async mode.
- A completed subagent item containing `CONSTELLATION_NATIVE_CHILD_OK`.
- The parent's first turn ending before completion.
- An automatic completion notification starting a second parent run.
- `CONSTELLATION_NATIVE_DELIVERY_OK` in that second run.

The native parent fetched the completed summary once **after** the automatic notification. The evidence includes that call rather than concealing it. There was no status/wait call before the wake and no polling loop. The timeline, not just the model's claim, establishes delivery order.

## Problems caught during testing/review

- Pi nested tool execution returns an outcome wrapper, not a bare tool result. The adapter unwraps it and propagates hook failures.
- T3 can serialize the same JSON twice and can encode failures as `OrchestratorMcpFailure`. Both cases are handled.
- Cancellation acknowledges a request before interruption finishes. Tests now verify both stages.
- Reusing a cancellation tool-call ID for a different task caused a real replay collision. Generated cancellation keys now include the task hash, with a regression test.
- Two independent, fresh-context code reviews caught stale documentation, misleading role-policy metadata, report-only wording, and global-option guard gaps. Those findings were addressed. Reviews used the same model family and are context-isolated, not cross-family independent.

## Limits

No finite test proves all future behavior. This evidence does **not** claim GUI pixel/rendering coverage, enforced read-only roles, OS isolation, automatic worktrees, every model/provider, every shell syntax, or compatibility with older T3 builds. The reusable live suite's deterministic parent is not mislabeled as an LLM or GUI test. The separate native timeline covers the actual automatic-wake path.
